File Organization Strategy
==========================

DOCUMENTATION (docs/) - Keep all guides and reference material here
  • Architecture & design documents
  • Implementation guides and examples
  • Quick start and getting started guides
  • Integration documentation

SOURCE CODE (src/) - All functional modules organized by phase
  • interview_engine/ - Resume extraction, parsing, skill assessment
  • phase3_scheduling/ - Interview scheduling with optimization
  • phase4_leave/ - Leave and absence management
  • phase6_escalation/ - Escalation case detection
  • ui/ - User interface components
  • utils/ - Shared utilities, threading framework, helper functions
  • resume_extractor/ - Document processing and extraction

CONFIGURATION (config/) - All settings and dependencies
  • config.py - Database, API, and system configuration
  • requirements.txt - Python dependencies for core system
  • requirements_ui.txt - Additional dependencies for dashboard

ENTRY POINTS (scripts/) - How to run the system
  • main.py - Start the HR automation pipeline
  • pipeline.py - Configure and run the processing pipeline
  • run_dashboard.py - Launch the Streamlit dashboard

OUTPUT (output/) - Results generated by the system
  • Processed results and exports
  • Generated reports and data files

LOGS (logs/) - System operational logs
  • Application and module logs
  • Audit trails


Threading Architecture
======================

Core Framework (utils/threading_manager.py):
  • ConcurrentBatchProcessor - Main executor with 3 modes:
    - Sequential: Standard execution
    - Threaded: ThreadPoolExecutor for I/O-bound tasks
    - Process: ProcessPoolExecutor for CPU-bound tasks
  • AsyncAuditLogger - Non-blocking event logger
  • WorkerPool - Background worker management
  • ThreadSafeLogger - Thread-safe logging
  • Helper functions: parallel_map(), run_async(), run_in_thread_pool()

Phase Integration:
  • Phase 1 (interview_engine) → parallel_evaluator.py (resume + candidate processing)
  • Phase 3 (scheduling) → concurrent_scheduler.py (optimization + conflict analysis)
  • Phase 4 (leave) → async event_hooks.py (FSM with threading)
  • Phase 6 (escalation) → batch_processor.py (case detection 8-10x faster)

Performance Improvements:
  • 5x speedup on multi-candidate evaluation
  • 6x speedup on schedule conflict resolution
  • 7x speedup on batch resume processing
  • 8-10x speedup on large escalation case sets (5000+ items)
